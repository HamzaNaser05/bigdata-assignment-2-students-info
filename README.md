# Student Records with MongoDB and Spark SQL

A two-stage data pipeline designed to demonstrate the functional differences between an **operational document store** (MongoDB: fast, index-driven operational lookups) and a **distributed analytical engine** (Apache Spark SQL: joins, array exploding, window functions, and aggregations over whole datasets).

---

## Architecture Overview

```
                      [ hw2-data.csv ]
                             |
                   (Part 1: Part1Import)
                             |
         +-------------------+-------------------+
         |                                       |
         v                                       v
[ MongoDB: university.students ]          [ students.json ]
  - Multikey Index: courseIds              (JSON Lines / .jsonl)
  - Single-field Index: gpa                      |
         |                                       |
    +----+----+                                  |
    |         |                                  |
    v         v                                  v
(Part 2)   (Part 3)                      (Part 4: Part4Analysis)
Course     GPA Query                       Apache Spark SQL
Query      & Combined Query                      |
(IXSCAN)   (IXSCAN)                              v
                                          [ course_stats ]
                                       (Saved back to MongoDB)
```

## Setup & Installation

### 1. Start MongoDB (Docker Example)
If using Docker, run MongoDB 7 with authentication enabled:
```bash
docker run -d --name mongo7 \
  -p 27017:27017 \
  -e MONGO_INITDB_ROOT_USERNAME=hamza \
  -e MONGO_INITDB_ROOT_PASSWORD=hamza \
  mongo:7.0
```

### 2. Java 21 / Spark VM Options (Crucial)
Because Java 21 restricts direct memory access used by Spark, make sure the following JVM arguments are supplied:
```text
--add-opens=java.base/sun.nio.ch=ALL-UNNAMED --add-opens=java.base/java.nio=ALL-UNNAMED --add-opens=java.base/java.lang=ALL-UNNAMED --add-opens=java.base/java.util=ALL-UNNAMED
```
*(These flags are already baked into `build.sbt` for terminal execution).*

## How to Run

### Via Terminal (SBT)

```bash
# Part 1: Import data, create indexes, and export students.json
sbt "runMain Part1Import"

# Part 2: Interactive query by Course ID (verifies IXSCAN)
sbt "runMain Part2CourseQuery"

# Part 3: Interactive query by GPA (verifies IXSCAN) and optional combined query
sbt "runMain Part3GpaQuery"

# Part 4: Run analytical Spark SQL queries and export course_stats
sbt "runMain Part4Analysis"
```

### Via IntelliJ IDEA
1. Open the project root in IntelliJ IDEA.
2. Allow SBT to sync dependencies.
3. Right-click on any file (`Part1Import.scala`, `Part2CourseQuery.scala`, `Part3GpaQuery.scala`, or `Part4Analysis.scala`) and select **Run**.
4. **For Part4Analysis in IntelliJ:** If you encounter `IllegalAccessError` on `sun.nio.ch.DirectBuffer`, open **Edit Run Configurations** and paste the `--add-opens` flags into the **VM options** box.

## Implementation Details

### Part 1: Data Parsing & Storage (`Part1Import.scala`)
- **Handling Arrays in CSV:** Custom field splitting handles unquoted arrays `[101, 102, 103]` without breaking CSV columns.
- **BSON Date Conversion:** Converts `dateOfBirth` string into BSON UTC Date (`java.util.Date` via `LocalDate` and `ZoneOffset.UTC`).
- **Indexing:**
  - **Multikey index** on `courseIds` to index each array element individually.
  - **Single-field index** on `gpa`.
- **JSON Export:** Writes each record as one standalone line using native `.toJson()` for `.jsonl` compliance.

### Part 2: Course Lookup (`Part2CourseQuery.scala`)
- Prompts for integer Course ID with loop-based error recovery.
- Runs `explain()` on the query cursor to verify the winning plan utilizes the `IXSCAN` stage.

### Part 3: GPA & Combined Query (`Part3GpaQuery.scala`)
- Validates GPA input strictly between `0.0` and `4.0` (exclusive).
- Verifies `IXSCAN` usage on the single-field GPA index.
- Provides an optional combined query (`Course = X AND GPA > Y`) using MongoDB's native compound `Document` filtering.

### Part 4: Analytical Spark SQL (`Part4Analysis.scala`)
- **Connector Integration:** Connects directly to MongoDB collection via MongoDB Spark Connector 10.3.0.
- **Reproducing Operational Queries:** Uses `array_contains(courseIds, 103)` and GPA range filtering.
- **Array Operations:** Uses `explode(courseIds)` to normalize the document structure into an `enrollments` view.
- **Per-Course Stats:** Aggregates `student_count`, `avg_gpa`, `min_gpa`, and `max_gpa`.
- **Window Functions & Tie Handling:** Uses `DENSE_RANK() OVER (PARTITION BY courseId ORDER BY gpa DESC) WHERE rank <= 3`. All students qualifying for the top 3 GPA tiers are preserved without skipping ranks.
- **Self-Joins:** Matches student pairs with identical `(firstName, lastName)` using `a._id < b._id` to exclude mirror duplicates.
- **High Achievers Query:** Joins `enrollments` with `course_stats` using `HAVING e.gpa > MAX(cs.avg_gpa)` to isolate students outperforming the average of every course they take.
- **Writing Results Back:** Saves the summarized DataFrame to MongoDB collection `course_stats` using `.mode("overwrite")` to ensure idempotent, crash-free execution.
